# Development Journal

This directory is the source of truth for recovering the `test atri` project
after context compaction, interruption, or a long pause.

Read order:

1. `STATUS.md` for the current state and next step.
2. `ARCHITECTURE.md` for the system shape.
3. `MEMORY_ARCHITECTURE.md` for the accepted unified multimodal memory design.
4. `REASONING_ARCHITECTURE.md` for the accepted always-on reasoning chain.
5. `DECISIONS.md` for locked decisions.
6. `MODULES.md` for module boundaries.
7. `API_EVENTS.md` for event and API contracts.
8. `WORKLOG.md` for actual completed work.
9. `TROUBLESHOOTING.md` for known debugging paths.

Working rule:

- Check docs first.
- If docs are stale or unclear, check source code.
- If source is still unclear, inspect running processes, logs, and runtime state.
- After resolving anything, update the relevant document.
